# 页面角色、计页与图内文字

在故事提案中说明采用的篇幅口径，随故事内容一起确定；已有明确口径直接执行，不另设确认关卡。

## 封面与封底

- 完整册默认由独立封面、N页正文、独立封底组成，N由项目确定，不固定十页。“十页漫画”只是N=10的例子，总计12张；“含封面封底一共十张”则在总数10内安排正文。用户只要正文、单页或局部修订时，只完成所要范围。
- 多章节合订一本时，全册共用一套封面/封底，不给每章自动加两张；明确分成数册时每册分别计算。连载中的章节完结不等于全书完结，不为尚未完成的整部作品编造封底或最终结局。
- 封面是一张独立设计：用书名、主角、主题气氛或视觉钩子吸引阅读；可以有章名，作者等署名仅使用已提供信息，不虚构。无需对白分格，不提前揭示关键反转。
- 正文从第1页开始叙事，不用标题海报或人设介绍占掉正文页数；最后一页正文完成本篇结局或约定的续集钩子。
- 封底给读者离开故事的余韵，可用环境、道具或人物背影回扣主题。默认不重复整张封面，不把必要结局放到封底，也不自动添加简介、二维码、假ISBN或广告。
- 封面/封底与正文沿用相同人设、场景和美术风格，但不强制采用漫画分格。已有成品只因技能更新不会自动新增两页或重编号；用户要求修订成品时再落实相应范围。

## 内部记录与导出顺序

页面计划区分三个概念：

| 字段 | 用途 |
| --- | --- |
| `page_kind` | `front_cover`、`story`或`back_cover` |
| `story_page_number` | 只有正文使用1至N，封面/封底为null |
| `export_index` | 全册实际导出顺序，含封面封底；由页面数组顺序确定 |

这些是项目制作元数据，不是图内可见文字。例如十页正文：封面是导出第1张，正文第1页是导出第2张，封底是导出第12张。以稳定文件名/ID区分，如 `cover-front`、`story-001`至`story-010`、`cover-back`，不要靠文件系统字母排序猜页序。

仅历史版本的基础排版脚本按`pages`数组导出，不自动添加封面、不印页眉页号，也不自动校验上述篇幅口径。它的`fit: "cover"`表示填充裁切，与封面类型无关。该历史脚本不得用于新页制作；当前整页原图转封装仍须核对页面角色与总数；元数据不得当作已有图片或已完成封面。

## 正文可见文字

默认正文只保留准确对白、必要旁白、拟声与剧情内物件文字。不加书名、页标题、页眉小字、页号、制作说明、场景编号、模型标记或水印。正文不预留空白页眉带；正常留白由画面节奏决定。

书名放封面；内部页标题与页号放文件名和分镜。用户要求印页码时，仅正文按约定在页脚安全区出现一次，不用“09/12”混合正文与总张数。用户要求章题扉页、明确选择封面兼叙事页或其他设计时遵从，并在页表记录其计页口径，不追问已明确的选择。

整页Prompt先区分“供执行看的信息”和“允许入画的文字”，例如：

```text
页面类型：正文。内部正文序号09、内部页名“原来你也一样”，这两项均不渲染。
允许可见文字：仅下面列出的对白、旁白、拟声与道具文字，逐条写明说话人和所在格。
正文无页眉、无书名、无页标题、无页码、无内部格ID；不复制人设图/场景设定板的标题和标签，不另加页眉留白带。
```

上述09仅示例；实际Prompt带入本页的准确文字。所有新页以本页可见文字表为整页原生一体化生成依据，不后期叠字。默认3:4竖版，用户显式指定其他比例优先；原图不裁切、补边或拉伸。PDF只将完整原页无改动转封装。

验收既查“应有文字是否正确”，也查“不应有的文字是否多出”。封面的大书名不属于正文页眉问题；剧情中的日记内容、短信、招牌或时间旁白不能因“无页眉”被误删。
