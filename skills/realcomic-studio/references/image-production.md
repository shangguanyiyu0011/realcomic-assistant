# 内置图片生成、改图与版本记录

只在用户要求成图、重画或完成漫画时执行。制作 skill、讨论流程、写分镜或输出 Prompt 均不构成图片调用任务。

## 默认使用内置工具

1. 使用当前宿主实际提供的内置生图/改图能力；有对应图片技能时先读取。Codex可使用其内置`image_gen`，Work、Dots不要求暴露同名工具。本技能的用户已明确选定内置图片模型，此选择优先于环境的一般豌豆默认规则。
2. 具体图片模型跟随内置工具当前配置。不猜测版本，只传当前工具schema公开的参数，不照抄其他宿主的调用方式，也不修改主代理模型设置。比例、构图和文字要求按该工具能力传入，实际像素以返回文件为准。
3. 内置路径不需要 `OPENAI_API_KEY` 或 `WANDOU_API_KEY`。不要因批量、修改尺寸或落盘需要改用 CLI/API，也不要要求用户提供密钥。
4. 内置工具不可用或失败时，保存已成功整页及分镜，说明具体失败。只有用户明确选择其他提供方或 CLI/API 路径时，才读取对应技能并执行；不静默切到豌豆或其他 API。

本包不包含联网脚本、密钥或第三方漫画仓库。图片生成依赖当前宿主确实提供内置工具；本地排版工具只处理已有图片。读取插件内资源使用当前宿主的资源/文件机制，引用相对本技能目录解析，不假设用户电脑路径在云端可读。

正式页之前执行 `preproduction.md`：先与用户确定故事内容，再依据身份参考确定故事造型，然后生成人设图并准备必要主场景设定。生成漫画时分别引用原始身份图、已采用人设图和相关场景图，不能把参考照片的棚拍服装自动当作已确认造型。只修改技能、只给策划/Prompt，或故事/造型尚待确认时，不启动漫画页生成。

## 整页原生生成与参考

正式图片阶段前，先完成本次确定整部/整卷/篇章范围内全量大纲、人物弧、全章节剧情、页表、逐格分镜与准确对白，汇总审查连续性、伏笔、页数与因果。禁止一章写完即出图再写下一章。开放连载明确本次完整制作范围，不缩减用户要求的整部范围；文本可分批协作，不要求一次API，也不跳过故事/造型确认。文本任务不调用图片。

- 所有新漫画页以完整页面为唯一图片请求单位，画面、分格、中文对白、气泡、旁白与必要图内文字原生一起生成。默认3:4竖版，用户明确另选比例时遵从。禁止逐格分别生图再拼页，禁止后期加字或补气泡。人设和场景参考可分别生成；逐格文本分镜仍保留，但须汇入整页请求。
- 实际查看每张参考，标明身份、人设、场景、风格或编辑目标用途。只附本页所需参考，始终以原始身份图锚定角色，不靠相邻画面层层传递造成换脸。
- 使用当前宿主公开schema传递参考；Codex的 `referenced_image_paths` 与 `num_last_images_to_include` 仅是宿主示例，禁止混用时不可混用。不杜撰ID或路径。
- 整页Prompt写明各格ID对应的动作、镜头、边框形状、主次、准确对白、说话人、气泡顺序、越框来源及遮挡层级，不机械复用双横格模板。执行 [book-design.md](book-design.md) 的封面/正文/封底与可见文字规则，不把人设图标签或制作页号复制进正文。
- 全量文本审查及前期素材就绪后，可先做一张代表页自检，再逐页展开；这是图片质量自检而非新审批，更不能用首章试作跳过全范围分镜。互不依赖的完整页可以并行，相互依赖的道具状态先核验。

整页 Prompt 示例（格描述是文本规划，不是独立图片请求）：

```text
用途：生成一张完整3:4竖版真人摄影漫画正文页；画面、三个画格、中文与气泡全部原生一体化。
参考：图1锁定女主身份，图2锁定男主身份；采用人设锁服装；场景图锁定咖啡馆空间。
布局：上方宽主格建立空间，下方两个不等宽反应格，左到右、上到下阅读；不用三个独立图片文件。
第一格：女主在吧台外右手举起未开封信封，男主在吧台内。女主气泡准确为“这封信，你放错了。”
第二格：男主抬眼看向她，气泡准确为“名字没写错。”
第三格：女主停顿看着信封，保持仍未开封和同一只手，无对白。
光线：阴雨傍晚窗外冷散射光和室内暖光，真实皮肤与材质。
正文无页眉、书名、页题、页号和格ID；仅出现指定文字。不得拼格或后期加字。
```

仅为规划示例，不代表真实图片或已锁定身份；实际依据采用剧本和真实参考。

## 结果落盘与检查

- 使用工具实际返回的原始图、原图数据或文件信息，不假定所有宿主都有`$CODEX_HOME`或本地生成图目录。不硬编码文件名，也不把“目录里最新一张”自动认作当前页。
- 当前宿主有可写文件工作区时，将采用原图复制到项目内的`pages/`或环境指定目录，按`ch01-page002-v001`之类稳定名字保存，保留工具原件。没有文件工作区时保留实际会话图片引用与采用版本，如实说明文件落盘/合成限制。
- 若当前宿主未提供可访问的原始文件，交付内置图片并如实说明本地合成受阻，不用截图或占位图片冒充原图。若工具返回可解码的原始图数据，可原样保存，之后核对像素和格式。
- 逐格检查身份、服装、手、道具的结构/数量/去向、相机侧与背景方向和表演；需要图内文字时逐字回读，同时检查多余页眉、书名、页题、页号等是否混入。只有检查通过的真实图片才标为 `approved`。
- 禁止用本地工具拼格、加字、补气泡、裁切、拉伸或补边凑比例；画面和文字修改均以整页为输入使用内置图片编辑。
- 处理透明输出时按当前工具 schema 请求透明背景并保留 alpha；正常摄影漫画页使用不透明背景。

## 超时、返工与记录

超时先查可用状态或已返回文件，不自动重放请求。保存已成功整页，清楚标明失败页。修订必须以现有完整原页为编辑输入并交付完整页，禁止独立生成目标格后拼回；保留未受影响内容和旧版本。修订前汇总同一页已经观察到的实质问题，Prompt 写明目标区域、保持项和改变项，尽可能一次修好关联问题；不凭假设扩展重画范围。改后回读目标区域及邻近对白、脸、手和道具，确认没有修好一处又破坏另一处。内置工具无法保证身份完全一致时如实标注，不无边界地重画。

每页至少记录页ID及所含格ID、版本、Prompt、实际输入及用途、实际工具名称、实际返回尺寸、原始及采用文件/会话引用、检查结论和必要的派生处理。模型标识只有工具实际返回时才记录；未公开时写“内置图片工具默认模型（具体标识未公开）”，不假称使用某个API模型。凭据不进入章节JSON或交付包。

保留未经处理的模型原生PNG及其哈希、实际宽高和请求比例；默认3:4，用户指定其他比例优先。以实际宽高检验比例，模型不符时记录并重试整页或报告，不裁切、拉伸、补边来冒充原生合规。不得把放大画布当成新增摄影细节。

PDF仅将完整原页按既定页序无改动转封装，不重采样、不拼格、不叠字、不改比例，并保留PNG。核对封面/正文/封底数量、页序及像素内容；当前工具不能无改动封装时先交原图并如实报告PDF限制。
