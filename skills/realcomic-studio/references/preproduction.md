# 人物与场景的前期设定

## 第一步：确定故事内容

先读本次请求与已有项目记录，区分已确定的故事事实和自己的提案。只有一个书名、题材、页数和人像时，先与用户共同确定故事，不直接锁服装或生图。

给出具体但便于修改的故事方案，通常用一个梗概加少量关键节点即可：主人公关系与背景、发生了什么、怎样推进或产生阻力、主要转折、结尾，以及希望读者感受到的情绪。按[页面设计口径](book-design.md)说明正文页数与封面/封底是否另计；这一阶段不必提前画满逐页分镜。问用户是否采用这套内容，或只问会实质改变内容的缺项；已有答案不重复问。

故事确认前不生成角色设定图、场景图或漫画页，也不先进入服装选择。可以实际查看人像素材、提炼文字资料、提供故事方向供讨论。完整剧本加“按这份做”、对具体方案的接受、或明确授权自行编剧，都可作为故事已确定的依据。单纯“帮我生成校园漫画，暂定十页”不能视为接受了助手尚未提出的具体情节。

记录`story.status / scope / synopsis / tone / central_conflict / ending / user_confirmation`；其中scope说明是整部方向、某篇章还是当前章节。确认依据来自实际用户消息，未确定留空，不编造接受记录。故事大改后再核实受影响的内容，既定角色与素材可先保留，不自动全部重做。

编剧方法见[story-development.md](story-development.md)。长篇首次讨论先给整部主线、主角欲望与主要阻力、人物成长方向、篇章走向；有限结局给终点方向，开放连载给可持续发生冲突的关系与当前篇章目标。提案阶段可先展示梗概；总方向已接受或用户授权自行推进后，必须补全本次整部/整卷确定范围全部章节的页表、逐格分镜与对白并全局审查，才进入人设、场景和漫画图片阶段，不因进入新章重复询问同一故事设定。

进入下列图片步骤前，先完成本次确定范围全部章节剧情、页表、逐格分镜与准确对白并汇总审查；不能用已确认故事梗概代替全量分镜完成。文本可分批完成，不要求一次调用。

## 第二步：参考照片不等于故事造型

故事确定后，实际查看上传人物图，区分原始面貌和照片中可更换的服装。结合已定故事给出具体、可修改的角色方案，再请求用户确定；不能只问“还有什么要求”，也不能已经开始出漫画后才询问。

校园故事的提案可包含：男主的角色名/故事年龄、日常服装组合、鞋、眼镜是否保留、发型与书包；女主的角色名/故事年龄、校服或日常服装、鞋、发型和配饰；共同的季节和校园类型。只提出当前故事真正需要的项目，不把用户变成填表员。涉及年龄等人物设定来自创作选择，不推断真人资料。

清楚标记哪些是用户已定，哪些是待确认提案。造型确认前不制作依赖该造型的人设图或漫画页；故事已经确定时，可先准备主场景文字卡。用户回复“可以/按这套/沿用照片衣服”等即为相应方案的确认，不再重复确认同一套造型。用户明确授权自行决定时记录该授权并推进。长篇先完成本次确定范围全量文本，再按已确认方案准备适用角色；范围外未来角色不阻塞本次制作，范围内页面所依赖的造型与参考必须先就绪。纯分镜、纯Prompt任务只完成文本，可在文本中标明待定造型，不要求先出图。

## 故事专用人设图

确认方案后，使用内置图片工具并附原始身份图，制作每个主角的故事人设图。常用为一张组合图：清晰正面半身/面部、正面全身、侧面或背面，再加故事需要的表情或关键配饰。视角数量服务后续镜头；用户已有符合造型的人设图时直接复用。

Prompt 明确：原图只锁身份；新方案决定衣服/发型/鞋/配饰；同一个人不同视角，不是多个长相相近的人；中性背景、人体比例与服装材质可读。多人分别制作，避免脸混合。不要把所有情绪、美术风格和剧情同时塞进人设图。

检查并记录五官与体型是否接近原图、各视角服装是否一致、鞋与眼镜是否符合确定方案、侧背面能否辨认造型。保存 `角色ID / 方案版本 / 用户确认记录 / 原始身份图 / 人设图版本 / 检查结果`。现成棚拍参考只能列为 `identity_reference`，不能直接改名为 `character_sheet`。未生成时文件路径留空，不虚构完成状态。

角色方案已确定、人设图通过实际检查后，在用户已授权的制作范围内继续；只有用户要求看人设图后再决定时，才增加该阶段的等待。变更某个角色的服装只重新确认受影响的方案，已定的其他角色不重复询问。

## 场景设定

从剧情提取主要地点，选出反复出现、需要正反打或动作连续性的场景。一次路过的次要背景不必各自生成多张资料图。

每个主场景建立：

| 字段 | 内容 |
| --- | --- |
| 场景 ID 与剧情用途 | 哪些页/格在这里发生，承担什么故事功能 |
| 基础环境 | 季节、建筑年代/风格、材料、色彩、天气与日夜 |
| 空间关系 | 入口、窗、桌、走廊、树或湖的位置；角色可行走路线与对话轴 |
| 视觉锚点 | 少量稳定特征，如绿色窗框、圆木桌、蓝色雨棚，不堆无关装饰 |
| 光线状态 | 光源、方向；雨天/傍晚等必要状态怎样变化 |
| 设定图与版本 | 实际生成的环境图、采用版本、可变化项与检查结论 |

根据这些卡片，用内置图片工具制作关键场景设定图。通常先做无主角的空间全景，必要时补一个有助固定正反打的视角或清楚的俯视空间说明。室外同一地点的晴天/雨天可共用空间锚点，改变光线天气，不能每次换建筑和入口。不要因为是校园就强制所有作品采用某一城市或特定真实学校。

正反视图分别写出相机在哪一侧、面向哪里，以及人物背后应出现的主要环境；物体自身的左右与屏幕左右分开记录。机位转到另一侧时重新核对背景，不把主视图水平镜像或重复同一背景当成正确反打。实际检查设定图中的出入口、站位、遮蔽区域与动线能否支持剧情；设定图正确也不代表后续成图自然正确。

场景文字卡可以在角色方案待确认时先准备，场景生成按当前授权阶段进行。需要主角入画的尺度测试必须使用已确定的人设图；普通环境图不引入未经设定的新角色。

## 正式制作前的实际状态

沿用 `assets/project-bible.example.json` 的状态字段：角色方案从 `pending_confirmation` 到 `confirmed`，人设图从 `not_generated` 到 `generated` 再到 `checked`；场景也区分文字设计与真实图片。用户明确免做某项或提供可复用素材时记为 `waived_by_user` 或 `reused` 并写依据，不伪装成新生成。

旧项目若只有原始照片和试作页，不追认试作剧情或原照片衣服已被用户确认。先恢复故事内容的实际确定依据，没有依据时先讨论故事；再补齐适用的造型、人设与主场景设定，之后继续正式页。续写读取[long-form-production.md](long-form-production.md)，区分采用剧本与真实成图的停点，不把未出图的后续剧情当成漫画已发生。只修改技能的请求，仅修改文件；不把本指南当成这轮生图授权。
