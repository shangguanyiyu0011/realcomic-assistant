# 故事、角色与连续性

## 先建立足够的信息

从已有素材恢复故事目标、角色、关系、地点、时间、转折、篇幅和交付阶段。缺少的普通创作细节可以提出合理设定并标为创作选择；真人身份、原文事实和既有章节状态不能杜撰。作者明确限制“只改分镜/对白/第几页”时沿用其他已定内容。

把一段小说改成漫画时，先列事件因果，再决定哪些信息用动作、表情、环境或对白承载。内心活动可以通过反应格或短旁白表达，避免把长段小说原封放入气泡。每格结束应有可见状态，能衔接下一格。

## 角色表

最小字段为 `id / name / identity / identity_references / wardrobe_proposal / wardrobe_confirmed / design_status / character_sheets / invariants / allowed_changes`。前期确认与人设图流程见 [preproduction.md](preproduction.md)。身份特征写能在参考里观察到且有助辨认的内容；服装、表情与光照不当成不可变的脸。未确定造型不能放入 `wardrobe_confirmed`，未制作的人设图留空。人物关系及年龄等故事设定来自用户原文或明确创作设定。

参考图按顺序标用途，例如：

1. 图1：角色A身份，保持五官关系、发型与体型。
2. 图2：角色B身份，不把两人的脸混合。
3. 图3：当前服装，仅迁移服装。
4. 图4：场景空间，不引入其中无关人物。

整页请求汇总本页各格需要的参考图（不逐格分别请求图片），核实文件可读。多人格检查谁在左、谁在右、谁说话和视线是否对得上；单人近景只传所需身份及必要场景锚点。

## 空间与动作

- 先有能解释相对位置的场景格，再切正反打；保持视线与屏幕方向。确需跨轴时用转场、全景或明确动作重新建立空间。
- 同一场景光源、日夜、天气和门窗位置应合理延续。换时间/地点要有过渡，不能由模型随意补齐。
- 拿在左手的物品不无故到右手，放下的物品要有落点；明显湿衣、伤痕或服装变化记录发生原因。
- 反应格可留白停顿，不强行让每格都有对白；对白先后和气泡位置应顺阅读方向。
- 同一格避免并置必须先后发生的互斥动作，例如“开门、坐下、递信、拥抱”应分节拍。

对关键道具维护少量可见不变量：属于谁、数量、颜色、结构/材质、可读内容，及当前在手中、包内还是地面。两个相似物件要有可辨差异与独立轮廓，不只依靠对白说明是两个。它们被放下、掉落或交接后，下一格不能又留在原容器中；取回、换手或移位需要有可推断的动作衔接。无需为无剧情作用的每件背景小物建表。

每个正反打与人物近景继续核对相机侧与人物身后的锚点，不因裁到半身就默认背景无关。空间关系从场景卡落实到当前镜头：机位改变应产生合理背景变化；环境的可站立区域、遮蔽范围、干湿状态等也要支持正在发生的动作。

## 连载状态

长篇与跨会话恢复按[long-form-production.md](long-form-production.md)执行。项目设定表中的`continuity.actual`记录实际采用成图最后状态，`continuity.script`记录已采用剧本的停点，`continuity.planned`记录后续设想，三者分开。纯编剧以采用剧本接续，成图制作以实际采用页面接续；两种停点都不是新增确认关卡。每格`state_in / state_delta / state_out`说明该格改变了什么。状态包括：

- 时间、地点、天气和场景相对位置；
- 人物服装、手持/存放道具及可见变化；
- 哪个角色已知道什么；
- 人物关系变化、未回收伏笔和后续必须履行的承诺。

新章先引用与任务阶段对应的采用版本；只有尚未采用的部分才标为计划续写，不把已采用剧本降为草案，也不将未成图剧情记成漫画已发生。将角色知道的信息、读者已看到的信息与作者设想分开，并标明属于剧本层还是漫画层；伏笔登记要有来源章/页/格、当前状态与回收方向，预计回收不等于已经回收。创作讨论只在当前项目记录，不改用户长期事实或全局规则。

## 局部修订

定位格 ID、所属整页采用版本、改动目标和保持项；以完整原页为编辑输入和完整页面交付，保存新版本，不独立重生画格拼回。仅改变机位时检查表情、视线和气泡区；改变动作或剧情时追踪状态依赖。与本格无关的脸、衣服、文字和其他页不随意重做。用户说“这张不像”时，指出可见差异并写针对性修订 Prompt，不能只增加“更一致”一词。

## 文本阶段输出

整章页表按[页面设计](book-design.md)区分页面角色、正文序号与导出顺序，同时写每页的主事件、阅读节奏、格数、边界形状与布局。避免整章同为“上图+下图”，也不要求每格都横平竖直。相遇页可用斜切主格和局部反应，雨中页可用竖长主格与伞沿越框，告白页可开放边框、给大画面和留白；这些只是选择思路，不是固定页序。破格明确人物从哪格越过哪条边、进入哪处留白、处于哪层，身体连续且不妨碍阅读。对话页按发言与反应安排格子，不自动拆成两张相似双人照。

喜剧或反转按铺垫、动作、反应和揭晓安排信息，必要时留无对白停顿格；不为了填满页数重复同一个笑点，也不把结局挪到封底。内部页名仅用于制作管理，生成前另列本页真正允许读者看到的文字。

普通请求用清晰表格或逐格段落即可，不强制生成整套空目录。需要制作/续章时保存项目设定与章节 JSON；`assets/chapter.example.json` 里的 `purpose / shot / prompt / state_*` 为制作字段，这些字段只用于整页生成规划及校验，不用于新漫画页的逐格拼版或后期叠字。
