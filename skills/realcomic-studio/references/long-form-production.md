# 长篇与连续章节制作

本指南用于多章、跨篇章或上百页的真人漫画；短篇只取当前需要的字段。
它补充 [前期设定](preproduction.md)、[故事连续性](story-and-continuity.md)与[页面设计](book-design.md)，不改变先确定故事与造型再制作图片的顺序。
用户只要策划或检查时，文本就是本轮交付；全量文本审查后才按页生图，按章仅为进度归档单位，不产生逐章审批或自动计划任务。

## 从全书到画格

1. **全书主线**：用一句话写主角持续追求什么、什么长期阻碍他、失败代价及预计终点；区分闭合长篇与开放式连载。
2. **篇章弧**：每卷或每篇章记录入口状态、核心问题、升级、转折、出口状态，以及对全书主线的推进。
3. **章节任务**：每章有具体欲望、阻力、关键选择、实际改变和下一章入口；章节不能只因页数到了而截断。
4. **页面任务**：每页说明要让读者发现、感受或误判什么，如何转入下一页；页数与格数服务动作和阅读节奏。
5. **画格任务**：沿用稳定格 ID、动作节拍、精确文字及 `state_in / state_delta / state_out`，不让同格承担互斥动作。

先完成本次确定的整部/整卷/篇章范围内全量大纲、人物弧、全章节剧情、页表、逐格分镜与准确对白，汇总检查全局因果、连续性、伏笔和页数后，再按页整页一体化生图。不得首章写完即出图再写下一章；文本允许分章协作，但须全量完成再进入图片阶段。开放连载先明确本次完整范围，不要求无限未来，不得擅自缩小用户要求的整部范围。范围外未来设想不得冒充已定剧本或成图。
闭合长篇预留可抵达的终点，开放连载检验人物关系与核心处境能否持续产生不同冲突。
不要把电视剧的幕长、小说字数阈值或剧本页数直接换算为漫画页数。

## 可变页数预算

- 分开记录全书预估正文页、当前篇章页、当前章页与实际采用页；预算写区间或暂估值并标依据。
- 每章先按叙事任务分配页段，再根据对白密度、空间交代、动作连续性和情绪停顿调整。
- 页数变动时复核转折位置、后续章节入口、引用的页 ID 和待回收伏笔，不机械给每章同页数。
- 正文页数与包装张数独立。封面和封底按一本完整册或用户指定分册规划，不为每章自动增加两张。
- 用户明确把章封面、扉页或番外计入总数时，按已给计页口径写入页表；不重复询问已明确的选择。
- 计划预算不是导出事实；只有采用的成品页才计入实际完成数。

## 故事圣经与索引

持续项目维护一份简短的故事圣经，保存确定依据和可追溯索引：

| 范围 | 应记录的最小内容 |
| --- | --- |
| 全书 | 核心冲突、主题问题、闭合/开放类型、预计结局、用户已定限制 |
| 篇章 | 弧 ID、起止章节、入口/出口状态、关键转折、未决假设 |
| 角色 | 稳定 ID、目标、误信/弱点、成长阶梯、与谁的关系如何变化 |
| 世界 | 时间线、场景 ID、空间锚点、规则与变化原因 |
| 制作 | 确认依据、采用剧本版本、采用图片/页/PDF 版本及资源位置 |

圣经只保存结论、状态和来源指针；长对白、逐格 Prompt、原图与场景设定分别放在实际资源中。
索引和摘要帮助找到素材，不能代替回看原图、已采用页和相关原文。
用户素材、创作提案、已确认设定、已采用成品分开标识；不从空路径或示例文件推断成品存在。
记录关键决策的来源和变更原因，修订受影响内容即可，不因局部修订重开整个项目。

## 角色成长、关系与知情

- 人物弧记录“起点行为 → 压力下选择 → 代价 → 新行为”，并注明对应章节；成长可以反复，不必每章进步。
- 关系弧记录相互目标、误会、信任/权力变化及转折的可见行为，不以抽象标签代替实际互动。
- 关键事实维护三层知情：**作者已定什么、各角色此刻知道什么、读者从所读版本知道什么**；分别记录已采用剧本与已采用漫画的知情状态。
- 未采用草案揭示了秘密，只能更新计划知情。采用稿可以更新剧本层的角色与读者知情；漫画层须等采用画面或正文文字实际揭示后再更新，不能因剧本写到就声称漫画读者已看到。
- 秘密揭示、谎言、短信、道具内容和旁白应核对谁能看见、听见或推断，避免角色提前行动如已知真相。
- 以时间线记事件顺序和故事内日期；倒叙另记展示顺序，不能把读者先看到的片段误当事件先发生。

## 伏笔与承诺登记

对会影响后文的道具、信息、誓言、疑问或关系变化建一条稳定记录，不为同一伏笔复制多个互相矛盾的台账。

| 字段 | 写法 |
| --- | --- |
| `id / kind` | 稳定 ID；线索、承诺、疑问或呼应 |
| `setup_plan` | 计划在哪章/页/格埋设、读者应注意到什么 |
| `payoff_plan` | 预期回收方式与大致篇章，可随故事修订 |
| `script_record` | 剧本层的埋设/回收版本及位置；未采用时为 `null`，另记该层状态 |
| `comic_record` | 漫画层的埋设/回收文件及页格；未成图或未采用时为 `null`，另记该层状态 |
| 每层 `status` | `planned`、`planted`、`paid_off` 或 `dropped_with_reason`；依据该层实际采用版本更新 |

同一条伏笔可在采用剧本中已回收、在已采用漫画中尚未埋设，分别记录状态即可。草稿写到伏笔不等于已采用；图片中实际不可辨认的关键线索也不能记作漫画读者已看到。
回收时核对是否足够早埋设、是否改变角色选择或读者理解；仅重复同一信息不算有效回收。
删除或改动旧章的埋设，应追踪后文依赖，更新预计回收或说明该线已舍弃。

## 计划、剧本与漫画状态

**剧本采用**表示当前文本被选为制作依据；**成图采用**表示实际图片已生成、检查并选作漫画内容。
同一章可以“剧本已采用、成图未完成”。纯剧本续写直接承接该采用稿，不能把已采用剧本降为待定计划；漫画制作则只把实际采用画面的事件记为漫画已发生，后续已采用剧本仍可作为制作依据。
`planned`、`generated`、`approved` 沿用主技能的图片状态；`approved` 是制作检查通过，不额外代表用户审批。
逐章简报可参考 [章节简报示例](../assets/chapter-brief.example.json)，它不是排版脚本的输入文件。

| 层 | 版本与实际状态 |
| --- | --- |
| 故事/剧本 | 提案、已确认依据、采用稿版本、计划结尾、尚待解决的改动 |
| 画格/页面 | 实际文件、已看图检查、采用指针、对白核验与页序 |
| 章节成品 | 已采用成品的实际结尾、实际知情与道具状态、导出文件及页数 |

一章未完成时，不用最后一格的计划状态覆盖最近一格已采用漫画的实际状态，也不用漫画的落后进度抹除已采用剧本的进展。
废弃或未采用版本仅留在版本记录，不进入相应层的采用连续性。

## 只加载当前任务相关资料

续章前读全书与当前篇章的已定方向、当前章任务，并按本轮阶段选择入口：纯剧本续写读取上章采用稿和剧本层状态；漫画制作读取最近已采用漫画的实际结尾、相关原图及待制作部分的采用剧本。
再按当前出场角色、场景、道具及未回收伏笔的索引取相关原文或原图；不用一次读完全部历史页。纯文本创作不依赖尚未生成的人设图或上章漫画。
若漫画阶段上章尚无成品，清楚标记采用剧本与待定计划各自范围，先完成不依赖前章成图的工作，不能据此更新漫画实际发生状态。
图片、文件和附件按当前宿主实际可访问方式读取；Work/Dots 不假设能访问本机 Windows 路径。
找不到某项资源时只暂停依赖它的画格或验收，继续可独立完成的故事、分镜或其他页面，并列出缺失项。
索引、文件名或缩略图不能替代查看需锁定脸、服装、空间或实际文字的原图。

## 章节收尾与旧章修订

每完成一章剧本或一批漫画，立即回填对应层的采用版本、结尾、角色和关系状态、道具位置、作者/角色/读者知情、伏笔埋设与回收；漫画另记实际采用页/格和文件。
写精确续写入口：下一章从什么时间地点、谁想做什么、当前障碍是什么、哪些资源版本必须沿用。
章节结尾可留下悬念，但本章的具体任务应有可辨的阶段结果；封底不承担正文尚未完成的结局。
修旧章先定位目标版本和改动项，再查依赖它的后续格、页、章、伏笔和知情记录。
只更新实际受影响的采用指针、成品与状态；未受影响的图片和对白保持。
若后续章已经成图，依据实际变化判断是否需要重做或仅更新说明，并回看相邻成品。
修改故事圣经或脚本时保留旧版来源；不得静默把已采用成品改写为新提案。
每次报告本轮真实完成的阶段、页数、文件与仍受阻部分，不承诺未实测的大规模稳定性。
