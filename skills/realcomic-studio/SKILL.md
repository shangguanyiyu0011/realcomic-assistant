# 真人漫画助手

将剧情做成真人摄影质感的漫画。人物保持真人脸与真实材质，漫画感主要来自分格、阅读节奏、对白和旁白。用户明确选择绘画风格时遵从，不把参考照片自动变成动漫脸。

## 全量文本先行与整页一体化（制作硬规则）

- 先明确本次完整制作范围：整部、整卷或用户指定篇章。该范围内的大纲策划、人物弧、全章节剧情、完整页表、逐格分镜和准确对白必须全部完成并汇总审查，通过全局因果、连续性、伏笔回收、页数与阅读顺序检查后，才进入图片阶段。不得写完首章就出图、再写下一章；不得擅自把整部范围缩成一章。开放连载先明确本次完整卷/篇章，不要求无限未来。
- 文本可分批或多人协作完成，但必须全量汇总审查后再生图；“全部完成”不要求一次 API 调用，也不免除已有故事/角色确认要求。只要文本就只交文本；明确局部修订只处理受影响范围与依赖，不重开无关全书。
- 图片阶段仍按故事已确定 → 角色造型已确定 → 故事人设图 → 必要场景图 → 正式漫画页的顺序。人设、场景参考可以分别生成，不是漫画画格。各阶段受当前用户授权及实际素材就绪状态约束。
- 所有新漫画页（含封面/封底）以**整页**为生成单位：画面、分格、中文对白/旁白/气泡与必要图内文字由模型原生一体化生成。禁止逐格分别生图再拼页、后期叠字/补气泡；逐格文本分镜和格 ID 仍保留，作为整页 Prompt 的结构，不是逐格图片请求。
- 默认 **3:4 竖版**；用户明确指定其他比例时按指定值。保留模型原生 PNG，不裁切、拉伸、补边或重排来凑比例。核对实际宽高；不符时记录实际尺寸并重试整页或如实报告，不把后期改比例冒充原生输出。
- 局部修订以现有整页为编辑输入和整页交付，指定目标格/区域并保留未受影响内容；禁止单独重生目标格再拼回。保存旧整页原图及版本，不覆盖原件。
- PDF 仅允许按页序将完整原页无改动转封装，保持像素内容和比例，不重排、裁切、叠字或降采样，保留原生 PNG；工具不能做到时先交原 PNG 并报告 PDF 限制。旧排版脚本及历史资料仅保留兼容用途，不用于新漫画页拼格/叠字。

## 先判断本次交付

- **策划、编剧、分镜或提示词**：完成所要的文本阶段，不调用生图。
- **制作成图或完整章节**：先执行下方故事、人设与场景准备，再在已有授权范围内落实页面；上传参考图不等于已认可照片中的服装。用户明确要求先看方案或试作页时按该阶段停下（需先完成本次确定范围的文本），不额外自建逐页审批。
- **续章**：先读项目设定与对应阶段的采用版本：纯编剧承接上章采用稿；漫画制作承接实际已采用画面及对应剧本。
- **局部重做**：按稳定格 ID 定位，输入并编辑整页，保留未受影响内容与旧版，检查相邻格；仅更新受影响整页及整章 PDF。
- **只排版**：仅将已有完整原页按页序无改动转封装，不拼格或后期加字；散格素材不能冒充整页成品。

从上下文推断篇幅、输出比例、阅读方向、视觉风格和文字方式。篇幅是项目参数，支持单页、短篇、上百页长篇与持续连载，不默认锁成十页。未定篇幅时提出可调整的规模建议并标明待定；完全缺省的阅读与视觉方式可提议中文对白、左到右/上到下、3:4竖版，将它们写为制作假设。用户显式比例优先；格数和版式按实际用途与剧情确定。

## 编剧与长篇规划

故事提案、编剧或重构剧情时读 [references/story-development.md](references/story-development.md)。长篇、多章、连载、跨会话续写或旧章修订时，再读 [references/long-form-production.md](references/long-form-production.md)。

- 先分清有预定终点的作品与开放连载。以主角欲望、阻力、选择及代价形成主线；主题通过行动和关系变化体现，不靠结尾旁白硬讲道理。
- 按**整部故事→篇章/卷→章节→页→格**组织。短篇可压成一条故事弧；上百页项目先稳住主线、主要人物弧和篇章走向，把本次确定范围内全部章节细化到完整页表、逐格分镜与对白，全量审查后再生图。
- 人物成长、关系、伏笔与时间线要能跨章追溯；区分作者、人物与读者各自知道的信息。分别保存已定设定、当前计划、已采用剧本及实际成图，不将草案当成已发生事实。
- 对白按角色意图、关系与说话习惯设计，场景写可见行动和转折。喜剧来自性格与困境的升级、反差和回收，不固定每页笑点或强制每章反转。
- 总方向已确定后，先完成当前授权范围全部文本并汇总审查，再分批逐页生图；分批不是逐章边写边做、逐章重新审批或定时任务。用户只要故事方案就交该阶段；用户要完整作品则先完成全量文本，再按页生成、按章汇总记录与核验，不以“长篇”作为只交大纲的理由。

## 先确定故事，再准备人设与场景

实际制作漫画前，读 [references/preproduction.md](references/preproduction.md)。默认顺序为：**与用户确定故事内容与本次完整范围 → 完成该范围全部大纲/人物弧/全章节剧情/页表/逐格分镜对白并汇总审查 → 与用户确定角色造型 → 制作故事专用人设图 → 建立主要场景设定 → 核对已完成分镜与版式 → 逐页一体化生成漫画**。可以先查看上传图以了解素材，但收到人像不意味着跳过故事讨论。

- **第一步确定故事内容。** 先恢复用户已给的题材、篇幅和限制，再提出可审阅的故事方案：讲谁的故事、起因、主要冲突/推进、情绪基调、转折和结尾/续集钩子。只有书名和“校园/恋爱”等宽泛题材时，不能自行把整套剧情当成已定稿直接出图；先用具体梗概与用户讨论并确定内容，不抢先问衣服或制作设定图。
- 用户提供完整剧本并明确要求照此制作、明确接受已展示梗概或明确授权自行创作时，故事已有相应依据，记录后进入角色方案，不重复索要确认。只要求编剧或策划时，该阶段文本就是交付，不强制推进生图。

- 新上传的人物图先作为身份参考，提出适合故事的角色与服装方案供用户确认。至少明确人物在故事中的角色、主服装、鞋、发型与关键配饰；年龄/气质等已有信息直接沿用，未确定且影响结果的才问。不得自动沿用参考图的棚拍衣服，也不得自行换装后当成用户已认可。
- **适用故事或角色方案尚未确定时，不制作依赖它的人设图、场景图或正式漫画页。** 长篇先完成本次整部/整卷范围的全量分镜与对白审查，再落实该范围图片所需角色与场景；范围外未来篇章不必预先画满。故事待定时只推进故事讨论和素材理解；故事已定、造型待定时，可准备不依赖造型的场景文字设定。用户已明确服装/要求沿用原衣或明确授权自行决定时直接采用并记录，不对同一事项重复确认。
- 方案确定后，依据原始身份参考制作本故事专用人设图，固定造型与必要视角；通过实际看图检查再作为页面参考。现成原图或上一版漫画不能冒充新的人设图。已有符合本次造型的人设图可复用；用户明确免做人设图时遵从。
- 根据故事提取反复出现或空间关系关键的主场景，设计场景卡及必要场景设定图，固定建筑/陈设、动线、关键物件和光线。先有场景设定再制作依赖它的漫画页，不只把“图书馆、教室、校园”几个地名重复写进 Prompt。
- 原始人物图、人设图、场景图分别标注用途与版本。人设图锁定本故事造型，原始图继续锚定身份；场景图不带入无关人物和剧情。

## 故事与身份

读 [references/story-and-continuity.md](references/story-and-continuity.md)，建立足够支撑本次任务的设定。

1. 提取主线冲突、角色目标、场景、必要信息与转折。改编原文时保留因果、人物关系和关键揭示；压缩对白可做，改变结局或重要人设须有依据。
2. 为角色分配稳定 ID。把身份参考、服装参考、场景参考、风格参考分开，先实际查看图片，再记录每张图的用途。风格图中的脸不能覆盖角色身份。
3. 有真人照片时使用实际参考，描述可见特征，避免臆测身份、经历或不可见细节。无照片可创作原创角色设定；用户要还原指定真人而缺少可读照片时，可先完成故事和分镜，缺失照片的格不可声称已锁脸。
4. 角色方案确定后再制作必要的人设视角、全身造型和表情参考；设定图视角组织见前期设定指南。按本次交付阶段执行，修改技能本身不触发生图。
5. 以已确定方案及已采用人设/场景图锁定本章发型、服装、配饰、道具、时间、天气、位置和空间轴线；将镜头间可变的动作、表情、景别单独写出。

## 分镜与画面提示词

一格表达一个清晰的动作节拍或信息变化。复杂连续动作拆格；用全景交代空间、用中近景推进动作与反应，不把所有格都写成摆拍特写。对白与动作匹配，气泡顺序可读，悬念有后续回收。

### 封面、正文、封底与文字

完整册的页面设计读 [references/book-design.md](references/book-design.md)。用户说N页漫画时默认指N页正文，完整册另有独立封面和封底；“含封面封底共N张”则按总数分配。多章作品按成册范围配置封面封底，不给每章自动增加两张。单页、局部重做或只要正文的请求不额外增加封面封底。沿用旧项目时保留其实际范围，不因修改技能而自动重排或重做。

- 正文第一张才是正文第1页，最后的剧情与结局也在正文中完成。封面承担书名与主题展示，封底承担收束与余韵，不占正文序号、不代替剧情页。
- **正文默认无页眉、无页标题、无书名小字，也不印页码。** 不在左上角或其他页边重复“书名｜09｜这一页的小标题”。书名用于封面；内部页名、页号、格ID与场景标签只放文件名、分镜和记录。对白、必要旁白、拟声和剧情中的物件文字正常保留；用户明确要求的章题或页脚页码按其设计执行，不把本规则误用为删除剧情文字。
- 先列清本页允许出现的准确文字，再生成；Prompt 明确哪些制作信息不可入画，成图检查页边与所有画格，不能只校验对白是否写对。

### 分页与版式节奏

先为整章逐页决定叙事重点、格数、大小关系和阅读动线，再生图。**不得把所有页默认做成上下两张等宽横图，也不得机械重复同一模板。** 用户明确要求统一版式时除外。

- 格数随动作和信息量变化，不固定每页两格。场景建立、强情绪或结尾可用一格通版；对白用错落的中格；连续动作可拆成数个窄格或局部特写。
- 在章节中按需要组合：大主画面加小嵌格、左右不等宽、上方全景加下方双格、三至五格的不规则布局、竖长格、留白停顿，以及跨格或通版画面。选择服务剧情，不为了变化强行装饰。
- 分格边界不局限于横平竖直：根据动作方向和情绪使用斜切、多边形、倾斜窄格、开放边框、画面重叠及留白间隔；日常对白可用稳定矩形，不把整章换成另一套重复的几何模板。
- 在适合的动作或情绪重点，允许人物的头发、肩膀、手、衣摆或伞等有意识地突破所属画格边框。写清越过哪条边、进入哪片留白、遮挡哪些边框及前后层级；身体来自同一画格同一人物，不凭空增加一张脸或一只手。气泡、面孔、关键道具和后续阅读路线不能被遮住。破格应在正常阅读尺寸下可辨，优先让有表现作用的头肩、手臂或道具跨边；几根发丝贴边、普通裁切或仅去掉边框不足以宣称人物跳出画格。破格用于强调，不强制每格每页都有。
- 连续页面检查视觉节奏；同一分格连续出现时判断是否有叙事理由，无理由就调整。相邻格同时变化景别和信息，不全是双人半身正反打。
- 各页仍需有清晰阅读方向，气泡不跨错格，不因不规则布局遮住脸、手和关键道具。嵌格或跨格应与主画面有明确关系。
- 制作前在内部页表记录 `layout`、格数、主画面、形状、阅读顺序及需要的 `breakout`/遮挡层级。角色方案的确认按前期流程执行；版式表本身不额外增加审批。
- 生图 Prompt 必须落到本页的具体空间安排，例如“左侧竖长主格，右侧两个近景小格”，不能仅写“版式丰富”。剧情文案使用格 ID 对应，未确定版式时不先写死“上图、下图”。
- 复用前一页作为风格参考时，分别指定继承的角色、色彩、字体和边框；分格仍服从本页页表，不能把上一页的构图一并复制。验收时核对实际画格数量、大小关系和阅读顺序，不能只看 Prompt 写了多样化就算通过。
- 所有上述版式均在整页原生生成中实现，不使用基础脚本拼格或图层工具后期叠字。创意页参考 [assets/expressive-page.example.json](assets/expressive-page.example.json)，它是整页规划，不是基础脚本输入。

每格至少记录：

| 项目 | 应写内容 |
| --- | --- |
| 标识与顺序 | 章节、页、格 ID；全章唯一的阅读序号 |
| 剧情作用 | 这一格推进的信息、情绪或动作 |
| 连续性 | 入格状态、当格变化、出格状态；适用的角色/服装/场景 ID |
| 镜头 | 景别、可实现的机位、人物左右与视线方向 |
| 画面 | 具体动作、手和道具、前中后景、真实光源 |
| 文字 | 说话人、精确对白/旁白、气泡位置与阅读顺序 |
| 执行 | 原始身份/故事人设/场景参考的顺序与版本、画格形状与越框要求、提示词、状态和采用文件 |

逐格文本应完整，但不得作为独立画格生图请求；汇入整页 Prompt。每格文本结构为：**本格任务 → 引用图片角色 → 不变身份/造型 → 场景与当前动作 → 镜头/空间 → 光线/摄影质感 → 留白或准确文字 → 必要限制**。不得只写“同上”“同一个人”而不带所需参考和关键不变量。

- 手机随手拍、纪实或电影摄影都是可选视觉方向；“iPhone 14”只在用户指定时使用，不宣称图片确由该设备拍摄。
- 通过自然皮肤纹理、合理透视、真实材质、来源明确的光线及表演细节落实写实；不靠“8K、电影感、完美脸”等空泛词代替镜头设计。
- 身份靠固定参考维持，画面变化靠本格动作和机位完成。文字描述和参考不能保证完美一致，须逐格看图。
- 需要更细的写真提示词时才调用可用的 `nuyoah-xiezhen-prompt`；需要电影风格解读时才调用可用的 `zy-cinematic-realism`。本技能本身提供完整漫画流程，不依赖它们才能编剧排版；用户既定模型和提供方优先，不重新询问已知选项。

## 生图与文字方式

执行图片任务时才读 [references/image-production.md](references/image-production.md)。**本技能默认使用当前宿主实际提供的内置生图/改图能力**；Codex中的`image_gen`是其中一种实现，Work、Dots按其当前可用工具执行。有对应图片技能时读取，工具名、参数与参考图传递方式以当前说明为准。具体模型由内置工具当前配置决定，不写死API模型名、不要求API key、不改主代理模型。此处是用户对本技能的明确选择，优先于“普通生图默认使用豌豆API”的一般约定。只有用户明确指定时才改用豌豆或其他提供方；内置工具不可用时不得自动切换到外部API。受阻时完成可独立交付的分镜、提示词和版式，并准确说明未成图部分。

整页是唯一漫画图片生成/编辑单位，`text_mode: integrated`。每次请求包含整页布局、每格动作与准确中文，逐字回读全部文字及归属；不叠加同一句对白。已存在的旧项目原图与记录保留，后续新制作/修订执行本规则，不自动重做旧成品。缺少实际图片时只交文本和页表，不以占位图冒充成品。

## 原图与 PDF 导出

交付原生整页 PNG。PDF 仅无改动转封装完整原页，保留原图和页序；不运行 `comic_tool.py render` 来制作新漫画页，也不能用 `contain/cover` 补边、裁切或缩放凑比例。历史辅助工具能力及限制见 [references/layout-tool.md](references/layout-tool.md)。没有可用原图或无损转封装能力时如实说明，不截屏冒充原图。

## 连续章节与修订

长篇按[长篇制作与续写指南](references/long-form-production.md)组织，用 [assets/project-bible.example.json](assets/project-bible.example.json) 建设定工作副本，按需用 [assets/chapter-brief.example.json](assets/chapter-brief.example.json) 记录当前章任务与接续点；这些是制作资料，不是排版脚本的输入。不要把示例事实带入用户故事。目录按需使用 `references/`（用户素材）、`story/`（设定和分镜）、`pages/`（原生整页及版本；旧 `panels/` 保留为历史目录）、`exports/`（最终页和PDF）；环境指定过程与交付目录时服从该约定，不移动用户原件。

- 角色与场景 ID 稳定；格 ID 如 `ch01-p001`，修订以 `v002` 区分文件，不改成另一个格。
- 记录每格提示词、实际参考图、采用文件、尺寸、生成状态、检查结论及必要的模型/处理信息。禁止保存密钥。
- `planned` 是分镜；`generated` 是确有图片；`approved` 表示已完成身份、连续性和文字检查，不表示必须额外请求用户批准。用户要求指定区域验收时须满足，但交付仍为整页。
- 分别记录**计划结尾、已采用剧本结尾、已采用成图结尾**。纯编剧续章承接采用剧本；漫画继续制作承接实际成图，并用剧本指导尚未生成的部分。不能把未生成或弃用格记作漫画已发生。
- 重做时保留原版本，更新目标所在整页的采用指针，关联格记录引用该整页版本；若剧情状态、服装或道具发生变化，检查后续受影响格并准确报告范围。

## 验收与交付

文本阶段核对人物行动的动机与代价、场景因果、分镜顺序、对白归属及连续性。长篇还核对篇章推进、人物变化的依据、伏笔与知情范围，以及当前章实际状态是否回填。正式页生图前确认本次适用的故事和造型已确定、人设图与必要主场景设定已实际准备。成图阶段另核对：真人脸与造型、手和道具、空间方向、动作前后、气泡归属/尾巴、中文逐字准确、是否混入未要求的页眉/标题/页号、对比度、裁切、实际像素。导出分别核对正文页数、封面/封底数量与PDF总页数，顺序为封面→正文→封底；PDF物理页码不当成正文页号。异形/破格页检查真实边界、越框位置、遮挡层级及阅读路线，不能把普通留白边缘的裁切误报为人物破格。

本地脚本成功只证明结构或渲染成功。实际查看导出页面，长篇可逐页缩略检查后对高密度文字区放大；未看过的脸或页面不可声称视觉验收通过。只改一格时聚焦受影响页和整章导出是否同步，不无故重跑未变图片。

交付结果、可下载文件、完成范围与真实限制。高分辨率以实际尺寸为准，PDF 标明栅格；明确未完成格和需要用户补充的具体素材。用户只要可复制 Prompt 或纯对白时，仅交所要文本。
